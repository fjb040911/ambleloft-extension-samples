# 扩展能力体验馆

把项目协作、聊天、通知、表单和业务提交放在一个可安装的扩展中体验。基础功能保存在本机，不需要企业账号；报销和推送可以连接随 Demo 提供的独立本机服务。

## 从这里开始

1. 安装并信任扩展，在侧栏打开「扩展能力体验馆」。
2. 在首页选择一个已有本地项目，按宿主提示授权，再关联一项团队任务。Demo 不会自动创建项目或替你授权。
3. 创建聊天草稿，打开后由你发送；随后再次打开同一聊天继续对话。创建草稿本身不调用模型。
4. 发布一条本地通知，在宿主消息中心查看，再查询、更新或撤回。相同事件标识重复发布不会新增一条通知。
5. 在普通聊天输入下方示例，体验声明式表单和 MCP Apps 卡片。聊天步骤需要宿主已有可用模型。

## 聊天示例

**不连接业务服务的信息收集：**

> 用扩展能力体验馆展示团队计划信息收集表单。

Agent 先查找模板，再展示 `team-intake`。包含文本、多行文本、人数、金额、日期、地区和必选确认。结果经宿主确认发送到当前聊天。它只收集信息，不代表正式创建业务记录。

**任务内交互卡片：**

> 用扩展能力体验馆的任务卡片登记去上海的差旅，金额 1200 元。

Agent 调用 `samples.extension-showcase.cardRender`。卡片内修改地点和金额，再确认保存。卡片保存的是本地演示记录，不会向财务系统提交。

**三步报销业务：**

> 用扩展能力体验馆报销差旅费。

Agent 选择本扩展 `travel` 表单。地区和日期经宿主确认保存为业务草稿；金额为 CNY 十进制字符串；最后勾选核对并再次确认提交，返回报销单号。需要先配置下面的本机报销服务。

## 可选本机服务

源码配套目录提供两个服务，安装扩展不会自动启动它们。

- 团队事件推送：在源码目录执行 `npm run service`，监听 `127.0.0.1:47831`。扩展设置 `serviceUrl` 为 `http://127.0.0.1:47831/events`，`connected` 为 true。
- 报销：执行 `npm run service:expense`，监听 `127.0.0.1:47832`。扩展设置 `expenseServiceUrl` 为 `http://127.0.0.1:47832`。可用 `EXPENSE_DB` 指定隔离数据库路径。
- 配置中的 `limit` 必填，可填 20。两个服务地址互不替代。
- Ctrl+C 停止服务；报销数据库保留提交账本。停服后删除自己指定的隔离数据目录可以重置模拟业务。

服务只供本机虚构数据演示，无企业认证。服务源码与安装包一起交付，但不会装入扩展后台自动运行。

## 恢复与边界

业务写入使用宿主生成的 submissionId。结果未知时不要重复点击写入，用「核实提交结果」查询；unknown、超时和断线均不等于未执行。返回上一步不会撤销服务上已经保存的草稿。相同业务草稿不会因为新 submissionId 产生第二张报销单。

停用、卸载、更新或模板变更后，旧表单不能继续执行业务；Demo 不自动迁移或重放。取消等待不能撤销已经发生的写入。撤销权限后访问应由宿主拒绝。

首页支持宿主中英文与主题切换；表单 YAML 文本为中文，不宣称支持自动模板本地化。MCP Apps 卡片和首页是两种隔离环境。

真实企业 IdP 部署验收、动态表单选项、附件、旧表单迁移及系统级提醒投递不作为本 Demo 已验收能力。安全输入测试请仅使用虚构值。SDK/CLI 仍是开发者预览，不是稳定协议发布。

项目授权与任务关联是两个步骤：设置页授权仅允许访问项目；请在首页点击“选择项目并创建任务”，创建本扩展的任务记录。系统提醒已接入宿主 Electron Notification，但本 Demo 尚未验收真实 OS 横幅与点击；remind 不代表已送达。

## 消息按钮和结果回报（v0.5.0 需求）

运行 `npm run actions:service`（Node 22.13+，SQLite 数据默认保存在当前目录 actions.sqlite），在扩展设置填写 `actionServiceUrl=http://127.0.0.1:47833` 并授予 configuration。服务不进入扩展安装包，也不会自动启动。

1. 在首页新区域选择 accepted 或 unknown，使用新的 eventKey 发布通知。
2. 在宿主消息中心点击“提交任务”，确认写操作。accepted 持有写锁；unknown 模式在服务保存完成后故意断开 HTTP 响应。
3. accepted 模式下用 `curl -X POST http://127.0.0.1:47833/complete -H 'content-type: application/json' -d '{"id":"执行记录 ID"}'` 模拟业务管理员完成任务。
4. 刷新执行记录，选择 invocation，点击“查询业务结果并回报”。只 GET 查询业务，不重新 POST 提交。unknown 模式能查询到已完成结果。

服务以宿主 invocationId 为唯一键；持久锁由宿主管理，启动不会重放任务。同一 reportId 的相同载荷可重试，改变载荷不允许；两个 revision 分别保护执行记录与消息，冲突不应解释为业务失败。撤回/过期与跨扩展访问由宿主拒绝。此服务仅为本机业务演示，不处理企业数据。

## 企业管理员与认证验收

编辑源码 extension.json 的 authentication.resources，将示例 HTTPS baseUrl/audience/scopes 换成已部署服务，再 build 和安装；声明不自动授权。IdP 注册公共桌面客户端，启用 Authorization Code + PKCE S256，允许 `http://127.0.0.1:{随机端口}/callback`，支持 audience 对应的 resource 参数。不要设置客户端 secret；宿主设置→账号填写 issuer/clientId，tenant 留空，策略在 IdP 配置。

首页支持静默查询（未连接返回 null）、明确连接、断开、资源内 GET。宿主选择器可拒绝授权；会话到期、HTTP 401、配置变化需要重新连接。可输入 `//other.example/tasks` 验证越界请求被拒绝；请求中撤权后不得返回旧账号数据。SDK 不返回 Token、不附加任意授权头、不刷新 Token，也不自建登录页。会话事件只提示本扩展重新查询。

受控验证用宿主真实认证代理与真实扩展进程，替换企业协议/网络端点；不代表企业生产 IdP 已验收。真实部署还需逐项检查取消、过期、配置修改、401 和撤权期间请求。详见本轮报告。

图标为 assets/icon-light.png 与 icon-dark.png（128px 静态 PNG），build 复制 assets，安装前由 CLI/宿主校验。无需动态 setIcon。支持浅色、深色及跟随系统；无 icon 的旧模板继续使用默认图标。
